4. 하단 백테스트 패널 기획서 – 수정본_유지혁

이 문서는 하단 백테스트(Backtest) 패널의 화면 구성, 상호작용, 계산식, 데이터 흐름을 상세히 정의합니다. 하단 백테스트 패널은 ‘좌측 필터 패널 → 중앙 버블차트 → 우측 상세 패널’에서 선별한 계정들을 실제로 따라 했을 때, 기준 코인(ATOM 또는 ATOMONE)의 보유 수량이 기간 내 어떻게 변하는지를 모의투자 방식으로 검증하는 최종 단계입니다.
본 프로젝트의 핵심 목표는 USD/USDT 수익률이 아니라 ‘목표 코인의 보유 개수 증가’이므로, 하단 백테스트의 모든 결과(손익, ROI, 최종 가치, 그래프)는 반드시 ‘코인 수량 단위’로 표현됩니다.
1. 핵심 컨셉
첫째, 백테스트는 실거래를 수행하지 않습니다. swap 로그 기반으로 ‘따라 했다고 가정했을 때’의 보유 수량 변화를 계산해 보여주는 검증 도구입니다. 둘째, 사용자는 최대 3개의 계정을 Slot A, Slot B, Slot C에 배치해 포트폴리오를 구성할 수 있습니다. 각 슬롯은 전략 후보를 의미하며, 너무 많은 계정을 한 번에 섞지 않도록 3개로 제한합니다. 셋째, 슬롯 배치는 우측 상세 패널 하단의 Slot A/B/C 고정 버튼을 통해 명시적으로 수행됩니다. 사용자가 ‘어느 슬롯에 넣을지’를 직접 선택하므로, 자동 채움으로 인한 혼란을 줄이고 의사결정의 주도권을 사용자에게 돌립니다. 넷째, 백테스트 결과는 ‘상단(분석)에서 고른 후보를 하단(검증)에서 돌려보는’ 전체 4단계 UX(필터링 → 계정보기 → 상세보기 → 백테스트)를 완성하는 결론 영역입니다.

2. 설계 의도 중앙 버블차트와 우측 상세 패널이 ‘이 계정이 어떤 성향인지’를 설명하는 단계라면, 백테스트 패널은 ‘그래서 이 계정을 내 전략 후보로 채택해도 되는지’를 검증하는 단계입니다. 특히 ATOM/ATOMONE 생태계에서 ‘보유 수량 증가’를 목표로 삼는 중급 투자자는, 계정의 영향력(AII)이나 순매수 성향(Net Flow)만 보고 바로 따라 하기는 어렵습니다. 결국 마지막 결정을 내려야 하는 순간에 필요한 것은 ‘기간 동안 실제로 코인이 늘어났는가’라는 단순하면서도 결정적인 검증입니다. 따라서 하단 백테스트가 사용자에게 결정으로 이어지는 실험실이 되도록, 슬롯 구성(후보 선택)과 비중 조정(전략 혼합), 그리고 실행(시뮬레이션)을 한 화면에서 끝낼 수 있게 설계했습니다.
- 패널 레이아웃 좌측 영역(약 35~40% 폭): 포트폴리오 구성 영역(슬롯 + 비중 + 초기자본/기준코인) 우측 영역(약 60~65% 폭): 시뮬레이션 영역(실행 전 안내 → 실행 후 결과 요약 + 그래프)
3. 좌측 영역 – Portfolio Composition (슬롯 및 설정)
3-1. Slot A/B/C 카드(3개 고정) 세 개의 슬롯 카드가 위에서 아래로 세로 정렬됩니다. 각 카드에는 다음 정보를 최소 단위로 포함합니다.
	•	슬롯 라벨: A/B/C (카드 좌측 상단)
	•	상태 텍스트: Empty Slot 또는 계정 표시명/축약 주소(예: cosmos1…8x3)
	•	비중(Weight %): 카드 우측에 크게 표기(예: 20%, 60%, 20%)
	•	보조 메타: AII 점수(0~100)를 보조 메타로 노출합니다. 보조 메타는 ‘과밀’해지면 오히려 슬롯이 복잡해지기 때문에, AII 점수를 노출해 사용자가 해당 계정이 어떤 계정이었는지를 기억하기 쉽게 합니다.
- 색/시각적 연결 Slot A/B/C는 백테스트에서 ‘전략 후보 3개’이므로, 각 슬롯은 고정 색을 가집니다(예: A=블루, B=핑크, C=그린). 이 색은 아래 요소에 일관되게 적용합니다.
- 슬롯 카드 좌측 컬러 바
- 우측 시뮬레이션 그래프에서 슬롯별 라인 색
- 중앙 버블차트에서 ‘이 슬롯에 들어간 계정’을 하이라이트하는 외곽선 색 이렇게 하면 사용자가 ‘A 라인 = A 슬롯 계정’임을 즉시 인지할 수 있습니다.
- 동작(슬롯 채우기/교체/삭제) 슬롯 채우기는 우측 상세 패널 하단의 Slot A/B/C 버튼을 통해 발생합니다.
- 슬롯이 비어 있는 경우: 선택 계정이 그대로 해당 슬롯에 들어갑니다.
- 슬롯에 이미 다른 계정이 있는 경우: 기존 계정은 즉시 제거되고, 선택 계정이 해당 슬롯을 대체합니다(교체 정책 단일화).
- 슬롯 비우기(삭제): 슬롯 카드 우측 상단에 작은 휴지통(또는 X) 아이콘을 두고, 클릭 시 즉시 Empty Slot로 전환합니다.
- 추가 규칙(중복 방지) 같은 계정이 Slot A와 Slot B에 동시에 들어가면 비교 의미가 약해지므로, 기본 정책은 ‘중복 배치 방지’로 한다.
- 사용자가 이미 Slot A에 있는 계정을 Slot B로 다시 지정하면: Slot A는 비워지고 Slot B로 이동합니다(이동 정책).
설계 의도 및 근거 슬롯 카드의 목적은 ‘정보를 많이 보여주기’가 아니라 ‘전략 후보를 비교 가능한 단위로 고정’하는 것입니다. 따라서 슬롯 카드에서는 최소한의 식별 정보 + 비중 + 보조 정보만 보여주는 것이 가장 명확합니다. 또한 Slot A/B/C 고정 색을 강하게 유지하면, 그래프 해석에서 색-대상 매칭이 매우 편리해집니다.

3-2. 비중(Weight) 조절 UI - 구성 좌측에 세로형 분할 슬라이더(Weight Bar)를 배치합니다. 이 슬라이더는 0~100% 범위를 3개의 구간으로 나눠 Slot A/B/C의 비중 합이 항상 100%가 되게 만듭니다.
- 손잡이(핸들) 2개로 3구간을 만들고, 각 구간이 A/B/C 비중이 됩니다. - 각 슬롯 카드 우측의 % 수치는 슬라이더 움직임에 실시간으로 연동됩니다.
- 비활성/잠금 처리 Empty Slot은 비중을 줄 수 없으므로, 해당 슬롯이 비어 있으면 그 구간은 0%로 고정됩니다.
예: Slot C가 비어 있으면 A/B만으로 100%가 자동 재분배됩니다(2슬롯 모드). ‘최소 2개 슬롯 필요’ 조건이 걸려있으므로, 실제 Run Simulation 가능 상태는 A/B 또는 B/C 또는 A/C 두 개 이상이 채워졌을 때만 됩니다.
설계 의도 및 근거 포트폴리오 시뮬레이션에서 가장 흔한 사용자 실수는 ‘비중 합이 100이 아닌 상태’로 실행하려는 것이라고 예측합니다. 비중 슬라이더를 ‘합이 항상 100’이 되게 설계하면, 사용자는 비중을 조절하는 데만 집중하면 되고 수학적 검증을 UI가 대신 수행하게 됩니다.

3-3. 초기 자본(Capital) 입력 / 기준 자산(Base Asset) 토글 - 구성 좌측 영역 하단에 다음 내용을 배치합니다.
	•	초기 코인 수량 입력 필드: 기본값 100
	•	기준 자산 토글: ATOM / ATOMONE
- 토글은 백테스트 결과의 ‘단위’와 ‘ROI 계산 기준’을 결정합니다. 예: 기준 자산이 ATOM이면 결과는 ‘최종 ATOM 수량, ROI(ATOM 기준)’으로 표현됩니다.
- 입력 제한
초기 코인 수량은 최소 100 이상을 권장값으로 둡니다. 0 또는 음수 입력은 즉시 에러로 처리해 ‘최소 100 이상을 입력해주세요.’ 라는 문구를 빨간 색으로 띄웁니다. 너무 큰 값의 입력은 시각적으로 의미가 없으므로 ‘코인의 수가 너무 많습니다.’경고를 띄웁니다.
설계 의도 및 근거
이 프로젝트는 ‘코인 수량 기반’이므로, 초기 자본을 USD가 아니라 코인 개수로 설정해야 목표와 계산이 일관됩니다. 또한 기준 자산 토글을 제공하면, 사용자(ATOM 편향/ATOMONE 편향)가 자신의 목표 코인을 기준으로 동일한 계정 조합을 다시 해석할 수 있습니다. 즉, 같은 전략도 ‘ATOM 기준으로 보면 늘었지만 ATOMONE 기준으로는 줄었다’ 같은 중요한 차이를 확인할 수 있습니다.

4. 우측 영역 – Simulation (Run Simulation / 결과 뷰)
4-1. 실행 전(Empty State) 화면 - 구성 우측 영역 중앙에 큰 CTA(Call To Action)로 ‘Run Simulation’을 두고, 아래에 조건 안내 문구를 노출합니다. ‘최소 2개 슬롯에 계정을 넣고, 비중 합 100%와 초기 코인 100개 이상을 설정하면 실행할 수 있습니다.’
- 버튼 활성/비활성 조건 계정 슬롯이 2개 미만이거나, 비중 합이 100%가 아니거나, 초기 코인 수량이 조건 미달일 경우:
- Run Simulation 버튼은 비활성화(회색) - 버튼 하단 안내 문구는 유지
조건 충족 시:
- 버튼 활성화 + 약한 글로우 효과
설계 의도 및 근거 빈 화면에서 결과 그래프를 보여줄 수 없기 때문에, 사용자가 ‘다음 행동이 무엇인지’ 즉시 알도록 행동 유도(Call to Action)를 전면에 둡니다. 특히 이 패널은 4단계 UX의 마지막 단계이므로, 여기서 사용자가 멈추면 대시보드의 목적이 달성되지 않습니다. 따라서 실행 전 상태는 기능 설명이 아니라 안내가 되어야 합니다.

4-2. 실행 상태(Loading) 및 전환 - 동작 Run Simulation 클릭 시:
- 버튼은 로딩 스피너로 변환 - 좌측 영역 입력(슬롯 삭제/비중 조절/초기 자본/토글)을 일시 비활성화(실수로 설정이 바뀌는 것을 방지) - 백엔드에서 시뮬레이션 결과를 계산 후 응답
백엔드 데이터 응답 수신 시:
- 우측 영역은 결과 뷰로 전환 - Run Simulation 버튼은 우측 상단의 작은 ‘다시 실행(↻)’ 아이콘으로 축소되어 남습니다. - 결과 요약 카드 + 성과 그래프가 등장
- 전환 애니메이션 의도 버튼이 단순히 사라지고 그래프가 뜨는 것이 아니라, ‘내가 누른 실행이 결과를 만든다’는 인과를 느끼게 하는 전환이 중요하다고 판단했습니다.
설계 의도 및 근거 백테스트는 이 대시보드의 결론이기 때문에, 사용자는 ‘내가 지금 중요한 계산을 실행했다’는 감각을 가져야 합니다. 전환 애니메이션은 미적 요소 뿐만이 아니라, 결과에 대한 신뢰감을 높이는 장치입니다.

4-3. 결과 뷰 요약 카드 - 구성 차트 상단에 세 개의 숫자 카드 배치
	•	Total PnL
- 정의: 최종 코인 수량 − 초기 코인 수량 - 예: 초기 100개 → 최종 112개라면 Total PnL = +12 ATOM
	•	ROI (%)
- 정의: (Total PnL / 초기 코인 수량) × 100 - 예: (12 / 100) × 100 = +12%
	•	Final Value
- 정의: 최종 코인 수량 - 예: 112 ATOM
각 카드에는 단위(ATOM 또는 ATOMONE)를 명시합니다.
- 툴팁/도움말 ROI, PnL 같은 용어는 카드 제목 옆에 (?)를 두고, 클릭 시 계산식과 예시를 짧게 보여줍니다. 
설계 의도 및 근거 사용자는 그래프보다 숫자 결론을 먼저 봅니다. 요약 카드는 결과를 한 번에 판단하게 하고, 그래프는 왜 그런 결과가 나왔는지(중간 과정)를 확인하게 합니다. 또한 본 프로젝트의 성격에 맞게 PnL/ROI/Final Value는 반드시 코인 단위로 보여줘야 설계 목표와 어긋나지 않습니다.

4-4. 결과 뷰 성과 그래프 - 그래프의 목적 이 그래프는 ‘추이’를 보는 것이 목적입니다. 즉, 최종값만 보여주는 것이 아니라, 중간에 얼마나 흔들렸는지, 어느 시점에 성과가 갈렸는지를 보여줘야 합니다.
- 그래프 형태(누적 코인 수량 라인 차트)
- X축: 좌측 필터에서 선택한 기간의 시간(일 단위 또는 시간 단위, 데이터 준비 수준에 따라) - Y축: 기준 자산 코인 수량(ATOM 또는 ATOMONE)
- 표시 라인
- Portfolio Total(굵은 라인): 슬롯 합산 결과 - Slot A/B/C(얇은 라인, 색은 슬롯 색과 동일, 토글로 On/Off 가능하게): 각 슬롯의 단독 성과 곡선 - Hold(점선): 초기 수량이 유지되는 기준선
설계 의도 및 근거 이 대시보드는 잘 번 계정 찾기만이 아니라 내 성향에 맞는 전략 조합 찾기까지 포함합니다. 따라서 중간 변동성(리스크)을 보여주는 추이 그래프가 반드시 필요합니다. Hold 기준선까지 함께 제공하면, 사용자는 따라 한 게 정말 의미가 있었는지를 즉시 판단할 수 있습니다.

4-5. 결과 뷰 보조 그래프만으로는 왜 올랐는지가 완전히 설명되지 않습니다. 그래서 결과 뷰 하단(또는 그래프 우측)에 작은 툴팁을 둡니다.
- ‘기간 중 가장 큰 기여 슬롯’ 요약 예: ‘최종 증가분 +12 ATOM 중 Slot B 기여 +8 ATOM’
설계 의도 및 근거 우측 상세 패널에서 이미 전략적 해석(타이밍/상관/AII 분해)을 했더라도, 백테스트 결과를 보면 사용자는 ‘결국 누가 수익을 만들었는지를 다시 묻게 됩니다. 결과 뷰 보조는 이 질문에 짧게 답하고, 사용자가 다시 상단 패널로 돌아가 추가 탐색을 하게 만드는 연결고리 역할을 할 수 있습니다.

5. 데이터 및 시뮬레이션 로직(swap 데이터 기반)
5-1. 사용 데이터 범위
- 백테스트는 swap 로그 기반으로만 동작합니다. - ‘실시간 체결’, ‘오더북’, ‘IBC 이동’, ‘스테이킹’, ‘외부 가격 체결 가능성’ 같은 요소는 포함하지 않습니다. - 이 백테스트의 목적은 ‘정확한 실현 수익 재현’이 아니라 ‘전략 후보 간 상대 비교’이며, 특히 코인 보유 수량 관점에서의 성과를 추정해 비교하는 것입니다.
5-2. 계정별 ‘단위 1코인 기준 성과 곡선’ 생성
기존 기획서의 포트폴리오 합성은 ‘각 계정에 대해 단위 1코인 기준 성과 곡선이 있다’는 가정 위에서 성립합니다. 본 수정본 기획서에서도 이 틀은 유지하되, 그 곡선을 swap 로그로 어떻게 만들지 정의를 더 명확히 합니다.
- 핵심 아이디어
계정마다 거래 규모가 다르기 때문에, 계정의 절대 거래량을 그대로 따라 하면 사용자 초기 자본(예: 100 ATOM)과 스케일이 맞지 않습니다. 그래서 사실을 왜곡하지 않는 선에서 스케일을 맞추는 방식이 필요합니다. 여기서의 스케일링은 ‘행동 패턴(언제, 어느 방향으로, 얼마나 자주 바뀌는지)’을 동일한 초기 자본 위에서 재현하기 위한 정규화입니다.
- 정의
- 기준 자산 B는 사용자가 토글로 선택한 ATOM 또는 ATOMONE입니다. - 각 계정의 swap 로그에서 B가 관여한 트랜잭션만 추려서 시간 순으로 정렬합니다. - 각 트랜잭션에 대해 B의 레그(notional)를 계산합니다. (권장: tx_B_leg = max(B_in_total, B_out_total)) - 계정의 선택 기간 전체에 대해 총합 total_B_leg = Σ tx_B_leg 를 만듭니다. - 각 트랜잭션의 ‘상대 강도’를 share_i = tx_B_leg / total_B_leg 로 정의합니다.. 이 share_i는 ‘이 계정이 그 시점에 얼마나 강하게 움직였는지’를 나타내는 정규화된 강도이며, 합은 1이 됩니다.
- 시뮬레이션(단위 1코인) 초기 상태를 (B 1개, 반대 자산 0개)로 둡니다. 그리고 각 트랜잭션 i에서, 계정이 실제로 한 방향(매수/매도)을 동일하게 따라가되 거래량은 share_i만큼만 따라갑니다.
- 계정이 B를 팔고 반대 자산을 산 트랜잭션이면: 보유 B 중 share_i 비율만큼을 swap으로 반대 자산으로 바꿉니다.
- 계정이 B를 사고 반대 자산을 판 트랜잭션이면: 보유 반대 자산 중 share_i 비율만큼을 swap으로 B로 바꿉니다. 이때 적용 환율은 해당 트랜잭션의 swap에서 관측된 in/out 비율을 사용합니다(즉, 외부 가격을 끼워 넣지 않습니다).
이 과정을 시간 순으로 누적하면, ‘단위 1코인으로 시작했을 때 시간에 따라 B가 몇 배가 되었는지’의 곡선 r(t)를 얻을 수 있습니다.
- 보정 규칙(현실성/안정성)
- 특정 시점에 반대 자산이 0인데 ‘반대 자산을 팔아 B를 사는’ 방향 트랜잭션이 오면, 그 트랜잭션은 실행 불가이므로 스킵하고 다음으로 넘어갑니다.
- 수수료/슬리피지는 기본값 0으로 둡니다. 백테스트는 모의 테스트이기 때문에, 수수료는 계산하지 않습니다.
설계 의도 및 근거 이 방식은 그 계정의 행동 패턴(언제 크게 움직였는지, 방향 전환이 잦은지)을 보존하면서도, 사용자 초기 자본과 스케일을 맞춰 비교 가능하게 만듭니다. 또한 외부 가격을 인위적으로 넣지 않고 swap 로그에 나타난 실제 교환 비율만 사용하므로, 사실에서 벗어난 해석으로 빠질 위험을 줄입니다.

5-3. 포트폴리오 합성 - 포트폴리오 초기 세팅 사용자가 입력한 초기 코인 수량 C0와 비중 wA, wB, wC를 사용합니다(합 100%).
- QA0 = C0 × wA - QB0 = C0 × wB - QC0 = C0 × wC
- 기간 종료 시점 코인 수량 각 계정의 단위 성과 곡선에서 최종 배율 rA, rB, rC를 구합니다.
- 예: Slot B 계정이 단위 1코인 기준 최종 1.12배라면 rB = 1.12
- 실제 포트폴리오 기준 최종 코인 수량
- Qfinal = QA0 × rA + QB0 × rB + QC0 × rC
- 손익 및 수익률 계산
- Total PnL = Qfinal − C0 - ROI(%) = (Total PnL / C0) × 100 - Final Value = Qfinal
설계 의도 및 근거 이 합성 방식은 각 계정의 성과 곡선을 같은 단위로 정규화한 뒤, 사용자가 설정한 비중만큼 섞는다는 직관적인 구조입니다. 따라서 사용자는 ‘A를 20% 넣고 B를 60% 넣으면, 대부분의 성과는 B가 만든다’ 같은 조합 사고를 자연스럽게 할 수 있게 됩니다.

6. 우측 상세 패널 Slot A/B/C 버튼과의 연동 규칙
슬롯 배치는 우측 패널에서 명시적으로 실행되고, 하단 백테스트는 그 결과를 즉시 반영합니다.
- 동작 규칙
- 우측 패널에서 Slot A 버튼 클릭 → 하단 Slot A가 즉시 선택 계정으로 갱신
- Slot B 클릭 → 하단 Slot B 갱신
- Slot C 클릭 → 하단 Slot C 갱신
슬롯이 비어 있든 차 있든, 결과는 ‘그 슬롯이 지금 선택 계정으로 바뀐다’로 단일화합니다.
- 사용자 피드백(토스트/스낵바) 교체는 즉시 일어나므로, 클릭 직후 화면 중하단에 스낵바로 다음 형태를 띄웁니다.
- ‘Slot B가 [이전 계정] → [선택 계정]으로 교체되었습니다.’
이 피드백은 사용자에게 ‘내가 무엇을 바꿨는지’를 명확히 알려줌으로써 실수를 줄입니다.
설계 의도 및 근거
백테스트는 ‘결론’이지만, 결론에 도달하는 과정은 우측 패널(해석)에서 시작됩니다. 사용자가 분석한 직후 같은 맥락에서 슬롯에 넣을 수 있어야, 스크롤 내려가서 다시 찾는 시간이 사라지고 4단계 UX가 끊기지 않는다고 판단했습니다. 또한 슬롯 지정이 자동이 아니라 명시적이면, 사용자는 ‘A는 안정형, B는 공격형’ 같은 저마다의 의미 부여를 더 쉽게 할 수 있을 것이라 판단했습니다.

	7. 예외 처리 및 오류 메시지
- 실행 조건 미충족
- 슬롯 2개 미만: Run Simulation 비활성 + 안내 문구 - 비중 합 ≠ 100%: 입력 불가 구조(합 자동 100)로 근본 예방. - 초기 코인 수량 < 100: 입력 필드 강조 + 안내 문구
- 데이터 부족/계산 불가
- 만일 특정 계정이 선택 기간에 유효 swap이 거의 없는 경우: r(t)를 만들기 어려우므로 Slot 카드에 ‘N/A(데이터 부족)’를 표시하고, 해당 슬롯은 시뮬레이션에서 제외되도록 합니다. (단, 사용자가 최소 2개 유효 슬롯을 채우지 못하면 실행 불가)
- 백엔드 오류: ‘시뮬레이션 중 오류가 발생했습니다. 잠시 후 다시 시도해 주세요.’를 버튼 근처에 붉은 텍스트로 표시합니다.
설계 의도 및 근거 오류 상황에서 조용히 실패하거나, 이유 없이 숫자만 비어 있으면 사용자는 시스템 전체를 불신할 수 있습니다. 따라서 실패/제외는 반드시 사용자에게 ‘왜’를 짧게라도 설명해야 합니다.

8. 사용자 플로우 요약
	•	사용자는 좌측 필터에서 기간·규모·행동 패턴을 설정하고 중앙 버블차트에서 후보 계정을 찾습니다.
	•	우측 상세 패널에서 계정의 전략적 특징(타이밍/상관/AII 구성요소 등)을 확인합니다.
	•	‘이 계정은 후보로 넣어볼 만하다’고 판단하면, 우측 패널 최하단의 Slot A/B/C 버튼 중 원하는 슬롯을 눌러 하단 백테스트 슬롯에 즉시 배치합니다.
	•	하단 좌측 영역에서 슬롯 비중을 조절하고, 초기 코인 수량과 기준 자산을 설정합니다.
	•	조건이 충족되면 Run Simulation 버튼이 활성화되고, 클릭 시 우측 영역에 결과 카드와 추이 그래프가 나타납니다.
	•	사용자는 결과를 보고 ‘A/B/C 중 무엇이 더 낫고, 어떤 비중 조합이 내 성향에 맞는지’를 반복 실험합니다.
설계 의도 및 근거 이 플로우는 ‘탐색(중앙) → 해석(우측) → 검증(하단)’이 한 번에 이어지는 구조입니다. 특히 슬롯 버튼을 우측 패널에 고정 배치하면, 사용자는 ‘좋다/별로다’의 판단이 든 바로 그 순간 백테스트로 연결될 수 있습니다. 그 결과로 본 프로젝트 대시보드는 정보 나열형 페이지가 아니라 전략을 고르고 검증하는 도구로써 기능할 수 있게 됩니다.
